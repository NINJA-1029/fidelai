# Financial State and Deterministic Analytics Engine

## 1. Concept and Authority

`FinancialState` is the single authoritative mathematical representation of a user's financial reality at any point in time. It is never generated by LLM hallucinations; rather, it is computed deterministically from underlying transactions, recurring obligations, income records, bills, and user preferences.

---

## 2. Mathematical Formulations

### Liquid Available Cash
```
Available Cash = Current Bank Balance - Upcoming Immediate Bills Due (<= 7 days)
```

### Emergency Fund Coverage (Months)
```
Emergency Fund Months = Liquid Savings / Monthly Fixed Expenses
```
Where `Monthly Fixed Expenses = Rent + Utilities + Subscriptions + Debt Minimums`.

### Savings Rate
```
Savings Rate = (Monthly Income - Total Monthly Expenses) / Monthly Income
```

### Deterministic 30-Day Cash Flow Projection
For days $t \in [1, 30]$:
$$Balance(t) = Balance(t-1) + \sum Income(t) - \sum ScheduledBills(t) - \overline{DailyVariableSpend}$$
Where:
- $Income(t)$: Expected incoming paycheck if day of month matches.
- $ScheduledBills(t)$: Unpaid obligations due on day $t$.
- $\overline{DailyVariableSpend}$: Historical 30-day average daily discretionary and variable expenditure.

## 3. Deterministic Risk Detection Triggers

1. Liquidity Deficit Trigger:
   - Condition: $\min_{t \in [1,30]} Balance(t) < MinimumCashBuffer$
   - Risk: `RiskType.LIQUIDITY`
   - Severity: `CRITICAL` if $\min Balance(t) \le 0$, else `MEDIUM`.
   - Amount Impact: $MinimumCashBuffer - \min Balance(t)$.

2. Spending Spike Trigger:
   - Condition: $CategoryExpense(CurrentMonth) > 1.4 \times MeanCategoryExpense(Past3Months)$
   - Risk: `RiskType.SPENDING_SPIKE`
   - Severity: `HIGH` if impact $> 10000$ INR, else `LOW`.

3. Goal Pacing Deficit Trigger:
   - Condition: $RequiredMonthlyContribution > AvailableMonthlySurplus$
   - Risk: `RiskType.GOAL_DEFICIT`
   - Severity: `MEDIUM`.

## 4. Uncertainty Model and Data Completeness

Every metric computed or extracted carries an explicit confidence level and status tag:

| Status | Definition | Example Application |
|---|---|---|
| `confirmed` | Verified from settled bank statement or explicit user confirmation. | Settled transaction, bank balance. |
| `estimated` | Deterministically extrapolated from historical moving averages. | 30-day projected balance, daily discretionary run-rate. |
| `uncertain` | Extracted from noisy text (e.g. SMS) with lower confidence or variable freelance income. | Irregular consulting income, parsed SMS with low regex match score. |
| `unknown` | Missing data point; system acknowledges absence rather than guessing. | Unrecorded tax liability or unlinked account. |

### Data Completeness Ratio
Calculated as:
$$DataCompleteness = \frac{\text{Count of Populated Core Dimensions}}{\text{Total Core Dimensions (Income, Balance, Fixed Costs, Buffer)}}$$
When $DataCompleteness < 0.70$, the Agent proactively prompts the user for clarification before generating high-stakes recommendations.
